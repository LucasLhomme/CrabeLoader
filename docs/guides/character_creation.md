# Creating Custom Characters in Disney Infinity 3.0: From Zero to Hero

A comprehensive, step-by-step developer tutorial for creating custom standalone characters in **Disney Infinity 3.0: Gold Edition** using **CrabeLoader V2**.

---

## 1. Overview & Architecture

With **CrabeLoader V2**, custom character creation is **100% Zero-Touch**:
* **No modification of game installation files**: You never edit or repack vanilla `.zip` archives.
* **Automatic SKU Allocation**: No manual SKU picking or registry collision chores; each SKU is derived deterministically from the actor name (a multiply-by-31 string hash, mirrored exactly on the Lua side) into the mod range `1000340`–`1000999`, and moved to the next free value on a collision.
* **Declarative Manifest**: Character definitions can be declared cleanly inside `mod.json` or via `Crabe.VirtualReader.exposeCharacter`.
* **Dynamic Gateway Injection**: AES-128 figure registry slots, `ActorList` rows, and `DataMap` dependencies are injected dynamically in memory.
* **Loose VFS Texture Interception**: Textures are served directly as loose `.tbody` files without huge 50MB+ archive repacking.

## 2. Character Anatomy

A custom standalone character consists of:
```text
mods/<mod_id>/
├── mod.json                     <- Declarative manifest with character configuration
├── characters/
│   └── <actor_name>/
│       ├── <actor_name>.bent               <- Skeleton & bone hierarchy
│       ├── <actor_name>.oct                <- Octane scene graph & submesh bounds
│       ├── <actor_name>.mtb                <- Material & texture bindings
│       ├── <actor_name>_0.vbuf             <- Vertex stream buffer (positions, normals, UVs, weights)
│       ├── <actor_name>_0.ibuf             <- Triangle index buffer
│       ├── <actor_name>.animtreeoverrides  <- Animation tree overrides
│       └── <actor_name>.dnax               <- Actor DNA (compiled Lua): model path, moveset, costumes
├── textures/
│   ├── <diffuse_hash>.tbody     <- Diffuse atlas texture (DDS DXT1/DXT5)
│   ├── <normal_hash>.tbody      <- Normal map texture (DDS DXT5)
│   ├── <icon_hash>.tbody        <- HUD icon texture (generated by --icon)
│   └── <actor_name>.mtb         <- HUD icon material, 80 bytes (generated by --icon)
└── deploy.ps1                   <- One-click deployment script
```

`<actor_name>` is the lowercase actor name (`sor_sora`), both for the folder and the files.

## 3. Fast-Track: Building a Character in 5 Minutes

We provide an automated CLI tool under `tools/character_pipeline/build_character.py` that handles extraction, model retargeting, binary byte swapping, and manifest generation in a single command.

### Prerequisites
* **Python 3.9+**, run from the CrabeLoader repository root.
* **Pillow** (`pip install pillow`), only when you pass `--icon`.
* The game path is set in `GAME_DIR` at the top of `build_character.py` (default: `D:\SteamLibrary\steamapps\common\Disney Infinity 3.0 Gold Edition`). QuickBMS must be present in `tools/QuickBMS/`.
* **`--name` must have exactly as many characters as `--base`** (`SOR_Sora` and `EMP_Luke` are both 8). Names are rewritten in place inside binary files, so the pipeline refuses any other length.

### Step 1: Run the Character Pipeline

```powershell
python tools/character_pipeline/build_character.py `
    --base EMP_Luke `
    --name SOR_Sora `
    --mod sora `
    --icon path/to/icon.png `
    --deploy
```

### What Happens Automatically:
1. **Extraction**: Unpacks the base actor's model (`EMP_Luke`) from `assets/characters/emp_luke/emp_luke.zip`, and its `.dnax` from the shared `assets/characters/characters.zip`, into a temporary workspace.
2. **Actor Retargeting**: Clones `.bent`, `.oct`, `.mtb`, `.vbuf`, `.ibuf`, `.animtreeoverrides` and `.dnax`, renaming only what must point at the clone:
   * `.bent`: the path to the clone's `.oct`.
   * `.oct`: the paths to the clone's `.mtb`, `.vbuf` and `.ibuf`, plus the body material's name, so the clone gets its own material hash and its textures can be replaced without touching the base.
   * `.dnax`: the clone's model path and its `.animtreeoverrides` path.

   Everything else keeps the base's name **on purpose**: animation clips (`EMP_Luke_Combo_Y`), the eye material, costumes and the base's other archives only exist under that name. Renaming them breaks the character. This is the exact recipe of a clone verified in game.
3. **HUD Icon Generation** (with `--icon`): Converts your PNG image into an Octane `.tbody` DDS texture and creates the 80-byte companion `.mtb` descriptor.
4. **Manifest Generation**: Generates `mod.json` with the required `character` block, and a `deploy.ps1`.
5. **Deployment** (with `--deploy`): Installs the mod into your game's `mods/<mod>/` folder. **An existing `mods/<mod>/` folder is deleted and replaced**, so pick a mod id that no other mod uses. Without `--deploy`, the package is built in `mods/<mod>/` under the current folder (or `--out`).

The clone starts as an exact copy of the base: same mesh, same textures, same moves. Replace its `.vbuf`/`.ibuf` (mesh) and ship its `.tbody` files (textures) to make it your own.

## 4. Declarative `mod.json` Reference

Here is the standard `mod.json` format for a custom character:

```json
{
  "id": "sora",
  "name": "Sora (Kingdom Hearts)",
  "version": "1.0.0",
  "description": "Custom standalone character Sora with Kingdom Hearts animations and Keyblade weapon.",
  "character": {
    "name": "SOR_Sora",
    "baseCharacter": "EMP_Luke",
    "displayName": "Sora",
    "icon": "SOR_Sora"
  }
}
```

### Field Descriptions:
* **`name`** *(required)*: The unique actor name of the character (e.g. `SOR_Sora`). Must match the actor folder `characters/<name_lowercase>/`.
* **`baseCharacter`** *(required for a pipeline-built character)*: An existing vanilla character (e.g. `EMP_Luke`, `TCW_Anakin`, `AVG_IronMan`) whose combat logic, voice routing, and DNA configuration are inherited. CrabeLoader only adds the clone's `ActorList` row and `DataMap` entries when this field is set; without it the game has no way to load the actor.
* **`displayName`** *(optional)*: Human-readable name stored in the character's figure registry slot.
* **`icon`** *(optional)*: The HUD icon identifier.

## 5. In-Game Testing & Verification

1. Launch `DisneyInfinity3.exe`.
2. Open the CrabeMenu overlay by pressing **`F5`** (or gamepad `Back` / `View`).
3. Navigate to **`Heroes`** -> **`Swap Character Model (104 Heroes)`**.
4. Select **`★ Modded Characters`** (also reachable directly as **`Heroes`** -> **`★ Modded Characters`**).
5. Select **`Load SOR_Sora`**.
6. Your character spawns immediately into the world!

If the list shows **`No modded characters detected`**, check `loader.log` for `Loader: characters:` errors (SKU conflicts, malformed `mod.json`).
